Internal API

These names are not exported and carry no stability guarantee. They are documented here so that every docstring in the package appears in the manual; prefer the exported entry points on the other pages.

Arnoldi and Lanczos steps

ExponentialUtilities.firststep! — Function
firststep!(Ks, V, H, b) -> nothing

Initialize an Arnoldi or Lanczos iteration: zero H, set Ks.beta to norm(b), and store the normalized starting vector b / norm(b) in the first column of V. A zero b leaves the first column untouched, with Ks.beta == 0 signalling the caller to stop.

Arguments

  • Ks: Krylov storage whose beta field is set.
  • V: basis storage; its first column is overwritten.
  • H: recurrence-coefficient storage, filled with zeros.
  • b: starting vector.
source
firststep!(Ks, V, H, b, b_aug, t, mu, l) -> nothing

Initialize an Arnoldi or Lanczos iteration for an augmented system: fill b_aug with the scaled powers t^i / i! * mu, zero H, and store the normalized concatenation of column l of b with b_aug in the first column of V. Ks.beta is set to the norm of that concatenated vector.

Arguments

  • Ks: Krylov storage whose beta field is set.
  • V: basis storage; its first column is overwritten.
  • H: recurrence-coefficient storage, filled with zeros.
  • b: matrix whose column l is the physical starting vector.
  • b_aug: augmented-part storage, overwritten in place.
  • t, mu: time and scale defining the augmented entries.
  • l: index of the column of b to use.
source
ExponentialUtilities.arnoldi_step! — Function
arnoldi_step!(j, iop, A, V, H, n = -1, p = -1) -> β

Take step j of the Arnoldi iteration: apply A to column j of V, orthogonalize the result against the previous iop basis vectors (all of them when iop >= j), store the coefficients in column j of H, and normalize the remainder into column j + 1 of V.

Arguments

  • j: 1-based index of the basis vector being extended.
  • iop: incomplete-orthogonalization length.
  • A: matrix, matrix-free operator, or augmented-operator tuple.
  • V: basis storage; column j + 1 is overwritten.
  • H: Hessenberg storage; column j is overwritten.
  • n, p: physical dimension and augmented size, or -1 when not augmented.

Returns

β = H[j + 1, j], the norm of the unnormalized new basis vector. A value below the caller's tolerance signals a happy breakdown.

source
ExponentialUtilities.lanczos_step! — Function
lanczos_step!(j, A, V, u, v, n = -1, p = -1) -> β

Take step j of the Lanczos iteration: apply the Hermitian operator A to column j of V, orthogonalize against columns j and j - 1, and normalize the remainder into column j + 1 of V.

Arguments

  • j: 1-based index of the basis vector being extended.
  • A: Hermitian matrix, matrix-free operator, or augmented-operator tuple.
  • V: basis storage; column j + 1 is overwritten.
  • u: diagonal recurrence coefficients; u[j] is overwritten.
  • v: off-diagonal recurrence coefficients; v[j] is overwritten.
  • n, p: physical dimension and augmented size, or -1 when not augmented.

Returns

β = v[j], the norm of the unnormalized new basis vector. A value below the caller's tolerance signals a happy breakdown.

source
ExponentialUtilities.coeff — Function
coeff(::Type{U}, α) -> U-compatible coefficient

Return the recurrence coefficient α in the storage type U: α itself when α already has type U, and real(α) when U <: Real and α is complex, as required for the real recurrence coefficients of a Hermitian problem.

source
ExponentialUtilities.realview — Function
realview(::Type{R}, V) -> AbstractVector{R}

Return a view of the real parts of V when V is a complex vector with real part type R, and V itself when V is already a vector of R. Writing through the complex case sets the real parts and leaves the imaginary parts untouched; callers use it on recurrence-coefficient storage that is real for a Hermitian problem but may be held in complex storage.

source
ExponentialUtilities.@diagview — Macro
@diagview(A, d = 0)

Return a view of the d-th diagonal of the square matrix A as a strided vector view, using the linear-indexing convention of the callers in this package: d <= 0 selects a subdiagonal starting at row 1 + abs(d), and d > 0 is offset by the matrix size. Writing through the view writes to A.

Arguments

  • A: square matrix.
  • d: integer diagonal offset, defaulting to the main diagonal (0).

Dense and subspace phi evaluation

ExponentialUtilities.phiv_dense — Function
phiv_dense(A, v, k; kwargs...) -> Matrix

Compute the matrix-phi-vector products for small, dense A by forming the augmented matrix of Sidje's formula and exponentiating it. k >= 1.

Arguments

  • A: small square matrix, typically a Krylov Hessenberg matrix.
  • v: input vector of length size(A, 1).
  • k: highest phi-function order.

Keywords

Forwarded to ExponentialUtilities.phiv_dense!: cache, expmethod, and expcache.

Returns

A newly allocated matrix whose column j + 1 is $\varphi_j(A)v$ for j = 0:k.

The phi functions are defined as

\[\varphi_0(z) = \exp(z),\quad \varphi_{k+1}(z) = \frac{\varphi_k(z) - \varphi_k(0)}{z}\]

Instead of using the recurrence relation, which is numerically unstable, a formula given by Sidje is used (Sidje, R. B. (1998). Expokit: a software package for computing matrix exponentials. ACM Transactions on Mathematical Software (TOMS), 24(1), 130-156. Theorem 1).

source
ExponentialUtilities.phiv_dense! — Function
phiv_dense!(w, A, v, k; cache = nothing, expmethod = ExpMethodHigham2005Base(),
            expcache = nothing) -> w

In-place form of ExponentialUtilities.phiv_dense: write $\varphi_j(A)v$ into column j + 1 of w for j = 0:k without allocating the output.

Arguments

  • w: output matrix with size(w, 1) == length(v) and size(w, 2) == k + 1, overwritten in place.
  • A: small square matrix with size(A, 1) == length(v).
  • v: input vector.
  • k: highest phi-function order, k >= 1.

Keywords

  • cache: optional (length(v) + k) by (length(v) + k) matrix used as the augmented-matrix workspace; allocated when nothing.
  • expmethod: matrix-exponential method applied to the augmented matrix.
  • expcache: optional reusable workspace for expmethod, as produced for exponential!.

Returns

The mutated w.

ExponentialUtilities._phi_almohy! — Function
_phi_almohy!(out, A, p, cache) -> out

In-place evaluation of phi_0(A), ..., phi_p(A) for a strided Float64/ComplexF64 matrix A (p >= 1), writing phi_j(A) into out[j+1] and using the reusable PhiPadeCache cache for all scratch storage. The out matrices double as the recovery buffers.

Arguments

  • out: vector of p + 1 preallocated matrices matching the size of A, overwritten in place.
  • A: strided Float64 or ComplexF64 square matrix.
  • p: highest phi-function order.
  • cache: reusable PhiPadeCache sized for A and p.

Returns

The mutated out. On numerical failure the entries are filled with NaN, cache.info[] is set to a nonzero return code, and no error is thrown; on success cache.info[] == 0.

source
ExponentialUtilities._phi_almohy_generic — Function
_phi_almohy_generic(A, p) -> Vector

Container-preserving evaluation of phi_0(A), ..., phi_p(A) (p >= 1): the returned matrices have the same type as A (e.g. an SMatrix input yields SMatrix results). Used for immutable/static matrices, where the in-place workspace path does not apply.

Arguments

  • A: square matrix whose container type is preserved in every result.
  • p: highest phi-function order.

Returns

A vector Rm of length p + 1 with Rm[j + 1] approximating phi_j(A). A numerically singular Padé denominator yields NaN results instead of throwing, so an adaptive integrator can reject the step.

ExponentialUtilities.symtridiag_eigen! — Function
symtridiag_eigen!(d, e, Z) -> (d, Z)

Diagonalize the real symmetric tridiagonal matrix with diagonal d and off-diagonal e (e[i] couples rows i and i + 1; e[end] is scratch) by implicit QL iteration with Wilkinson shifts. On return d holds the eigenvalues, in no particular order, and Z holds the corresponding eigenvectors in its columns, provided Z was the identity on entry. The rotations are accumulated into whatever Z contains, so passing a non-identity Z yields Z * Q. Works in place on the given buffers and allocates nothing.

Accumulating the rotations costs O(n^3), against O(n^2) for LAPACK's MRRR (stegr!). It is nonetheless the faster choice on the Lanczos tridiagonals this path produces, whose decaying off-diagonals deflate in few sweeps; on generic tridiagonals it falls behind LAPACK past n of roughly 130.

Arguments

  • d: diagonal on entry, eigenvalues on return.
  • e: off-diagonal workspace with length(e) >= length(d); destroyed on return.
  • Z: matrix the rotations are accumulated into; pass the identity to obtain the eigenvectors in its columns.

Returns

The pair (d, Z). Throws an error if an eigenvalue has not converged after 30 * length(d) QL iterations.

source
ExponentialUtilities.expT! — Function
expT!(α, β, t, cache) -> view into `cache.v`

Apply the subspace exponential $\exp(tT)$ to the first unit vector, for the real symmetric tridiagonal subspace matrix T with α on the diagonal and β on the super-/subdiagonal, by diagonalizing T with ExponentialUtilities.symtridiag_eigen!. α and β are copied into cache first and are not modified.

Arguments

  • α: diagonal of T.
  • β: off-diagonal of T, of length length(α) - 1 or length(α).
  • t: scalar time or scale factor.
  • cache: StegrCache workspace sized for at least length(α).

Returns

A view of cache.v[1:length(α)] holding $\exp(tT)e_1$. The view aliases the cache and is overwritten by the next call with the same cache.

Caches and method selection

ExponentialUtilities.get_expcache! — Function
get_expcache!(C, A, expmethod) -> workspace or nothing

Return a reusable exponential! workspace (as produced by alloc_mem(A, expmethod)) stored in the cache C, allocating one the first time each distinct extended-matrix size is requested. A small list of workspaces is kept because a single integrator step may evaluate phi functions of several different orders (and hence sizes) against the same cache; they all share the one concrete workspace type W the cache was built for.

The typed store only holds workspaces for the default ExpMethodHigham2005Base (the method the cache's W was derived from); every other method dispatches to the fallback returning nothing, so the caller uses the two-argument exponential!. nothing is likewise returned for element types with no alloc_mem preallocation (W === Nothing, e.g. BigFloat). Dispatching on the method type keeps the return concretely typed (W or Nothing, never a union).

Arguments

  • C: an ExpvCache or PhivCache holding the workspace store; mutated when a new size is first requested.
  • A: prototype matrix; only size(A, 1) and the element/storage type determine the workspace.
  • expmethod: reduced matrix-exponential method.

Returns

The cached workspace wrapper for size(A, 1), or nothing for non-default methods and for element types without an alloc_mem preallocation.

source
ExponentialUtilities.pade_order_for_type — Function
pade_order_for_type(::Type{T}) -> Int

Return the smallest diagonal Padé order k whose (k, k) approximant to exp(x) reaches the precision of the floating-point type T for |x| <= 1, using the error bound (x/2)^(2k+1) / (2k+1)!. Types with at most 64 bits of precision return 13, the order used by the Higham 2005 algorithm; higher precision types search upward from 13, capped at 500.

Arguments

  • T: numeric element type whose precision determines the order. Complex types use the precision of their real part.
